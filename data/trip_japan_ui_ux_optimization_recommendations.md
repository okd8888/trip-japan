# 自駕旅遊行程規劃表 UI／UX 與功能優化評估

> 評估對象\
> - 目前版本：`https://okd8888.github.io/trip-japan/`\
> - 參考產品：`https://japan-travel-planner-orui.onrender.com/`\
> - 評估日期：2026-09-09\
> - 評估方向：以「自駕旅遊中實際使用」為核心，而不是單純增加功能。

------------------------------------------------------------------------

## 1. 評估結論

目前的「旅遊行程手冊」其實已經不是單純的行程表，而是具備：

-   今日行程
-   每日路線
-   航班
-   住宿
-   花費記錄
-   分類統計
-   幣別換算
-   打包清單
-   行程編輯
-   JSON 備份／還原
-   CSV 匯出
-   Cloudflare Worker 跨裝置同步

等功能的 **個人旅遊 Dashboard / Trip Companion**。

因此，下一階段不建議繼續以「再增加更多功能」作為主要方向，而應該把重點放在：

> **讓使用者在旅途中，用手機打開網站後 3～5
> 秒內，就知道「現在在哪裡、下一站去哪裡、幾點要走、要開多久、停哪裡、下一件重要事情是什麼」。**

# 2. 目前版本值得保留的設計

## 2.1 「今天」作為第一入口是正確方向

旅途中使用者通常不會想先看完整 6～7 天行程。

真正需要的是：

-   今天去哪裡
-   下一站是哪裡
-   幾點出發
-   車程多久
-   是否要預約
-   停車在哪裡
-   飯店在哪裡
-   晚上還剩什麼行程

因此目前以「今天」作為主要入口的方向應保留，而且建議進一步強化。

------------------------------------------------------------------------

## 2.2 行程、花費、匯率整合在同一網站非常實用

這是目前產品很有價值的地方。

一般旅遊規劃工具通常偏重：

-   行程安排
-   景點收藏
-   地圖

但實際旅途中還會頻繁使用：

-   日幣換算
-   今天花多少
-   住宿資訊
-   航班
-   打包清單

目前將這些功能集中在同一個網站，比單純的「行程規劃器」更接近真正旅行時會使用的工具。

------------------------------------------------------------------------

## 2.3 LocalStorage + JSON 備份的架構適合個人使用

目前資料先存在瀏覽器：

-   不需要登入
-   不需要資料庫
-   GitHub Pages 即可運作
-   開發與維護成本低

再搭配：

-   匯出 JSON
-   匯入 JSON
-   `trip.js`
-   Cloudflare Worker

其實已經形成不錯的「單機 → 可同步」漸進式架構。

這部分不建議為了模仿其他產品而全面改成複雜會員系統。

------------------------------------------------------------------------

# 3. 參考產品應該「參考什麼」，而不是直接模仿

參考產品目前為動態 Web
App，公開頁面的文字內容無法由一般靜態抓取完整取得，因此不應在沒有實際資料的情況下臆測其內部功能。

建議真正參考的重點不是「它有什麼功能，我也全部做」，而是觀察：

1.  首頁第一眼如何呈現旅程
2.  行程卡片的資訊密度
3.  日期切換方式
4.  景點與交通資訊如何分層
5.  手機操作是否容易單手完成
6.  編輯與瀏覽是否清楚分離
7.  空白、字級、卡片、icon 的視覺一致性
8.  是否讓「下一步行動」非常明顯

你的產品定位可以與一般 Japan Travel Planner 拉開：

> **不是做「規劃日本旅遊的平台」，而是做「真正開車旅行時每天會打開的自駕旅遊助手」。**

這個定位更適合目前已經建立的功能。

------------------------------------------------------------------------

# 4. 最大問題：資訊很多，但「旅途中最重要的資訊」還不夠突出

目前首頁包含：

-   行程圖表
-   今天
-   旅程進度
-   倒數
-   下一個亮點
-   目前花費
-   航班
-   打包清單
-   每一天路線

功能完整，但資訊的重要程度不一樣。

旅途中使用者最常問的是：

> **我現在下一站去哪？**

因此建議重新定義首頁資訊階層。

# 5. 建議重新設計「今天」頁

建議由目前偏 Dashboard 的方式，改成 **Today Command Center**。

## 第一區：Today Hero

``` text
DAY 3 · 12/09（三）

沖繩北部海岸線
古宇利島 → 美麗海水族館 → 備瀨福木林道

☀ 24°C
🚗 今日預計 126 km
⏱ 約 3 小時 10 分車程
🏨 今晚：Hotel XXXXX
```

目的不是裝飾，而是讓使用者第一眼掌握今天。

------------------------------------------------------------------------

## 第二區：Next Stop

這應該成為整個手機首頁最重要的卡片。

``` text
NEXT STOP

09:30
古宇利島

距離        28 km
預計車程    38 min
建議出發    08:50

停車：古宇利海洋塔 P1
MapCode：485 693 424*66

[ Google Maps 導航 ]   [ 已抵達 ]
```

### 為什麼重要

自駕旅途中最大的操作不是「查看行程」，而是：

> **開導航。**

所以每個景點都應該能一鍵開：

-   Google Maps
-   Apple Maps（選配）
-   MapCode（日本自駕非常實用）

# 8. 增加「行程狀態」

每一站建議有三種狀態：

``` text
○ 尚未前往
● 現在
✓ 已完成
```

例如：

``` text
✓ 飯店早餐
✓ 波上宮
● 美國村
○ 殘波岬
○ 飯店
```

首頁就可以自動把：

> `● 美國村`

當成目前行程，下一個：

> `○ 殘波岬`

自動變成 Next Stop。


# 12. 「編輯模式」與「旅行模式」應明確分離

目前最大的 UX 風險之一，是：

> 查看行程與編輯行程的功能存在於同一個資訊架構。

建議建立兩種模式。

## 旅行模式

只保留：

-   今天
-   行程
-   Navigation
-   花費
-   匯率
-   航班
-   飯店
-   打包

## 編輯模式

才顯示：

-   基本資料
-   修改目的地
-   日期
-   航班
-   住宿
-   新增景點
-   刪除景點
-   重排行程
-   JSON
-   同步設定
-   trip.js

# 20. Desktop 與 Mobile 不應只是 RWD 縮放

## Desktop

適合：

-   規劃
-   編輯
-   地圖
-   拖曳排序
-   一次查看多天
-   費用統計

建議：

``` text
┌──────────────┬──────────────────────┐
│ Day List     │                      │
│              │     Route / Map      │
│ Day 1        │                      │
│ Day 2        │                      │
│ Day 3        ├──────────────────────┤
│              │ Timeline             │
│              │                      │
└──────────────┴──────────────────────┘
```

## Mobile

適合：

-   今天
-   下一站
-   Navigation
-   記帳
-   匯率
-   飯店

因此應該：

> Desktop = Planner\
> Mobile = Travel Companion

這會是非常重要的設計原則。

# 27. 強烈建議加入 PWA

自駕旅行常遇到：

-   山區
-   地下停車場
-   網路不穩
-   漫遊速度慢

因此這個專案非常適合 PWA。

至少 Cache：

-   HTML
-   CSS
-   JS
-   行程 JSON
-   住宿資料
-   航班
-   景點基本資訊

即使沒有網路，也能看到：

``` text
今天去哪裡
飯店地址
MapCode
電話
預約時間
```

這比再增加很多線上功能更重要。

# 28. 不建議現在優先開發的功能

以下功能不是不好，而是目前 ROI 較低：

## AI 自動產生整趟行程

先不要優先。

原因：

真正困難的是：

``` text
產生行程
```

# 31. 最值得從參考產品吸收的設計思想

不建議把目標設定成：

> 「做得跟另一個 Japan Travel Planner 一樣。」

比較適合的是：

> **吸收成熟旅遊 Planner
> 的視覺層級、卡片結構、日期導航與操作簡潔度，但保留目前產品在自駕、花費、匯率、住宿、離線與個人化方面的特色。**

你的專案最有機會形成差異化的地方是：

``` text
一般 Travel Planner
       ↓
規劃去哪裡

你的 Trip Handbook
       ↓
今天怎麼玩
       ↓
下一站怎麼去
       ↓
車停哪裡
       ↓
幾點要走
       ↓
今天花多少
       ↓
晚上住哪裡
```

# 32. 最終建議

如果只選 **5 個項目** 做下一版，建議依序做：

1.  **Today 頁重新排版，以 Next Stop 為第一核心**
2.  **每日行程改成 Timeline**
3.  **所有景點加入一鍵 Google Maps Navigation**
4.  **加入自駕資訊：車程、距離、停車、MapCode**
5.  **手機 Bottom Navigation 與編輯／旅行模式分離**

完成這五項後，使用體驗的提升會比一次新增十幾個功能更明顯。

------------------------------------------------------------------------

# 33. 建議產品定位

最後建議把產品定位從：

> **旅遊行程手冊**

進一步明確成：

> **Self-Drive Trip Companion --- 自駕旅遊行程助手**

核心設計原則：

> **Plan on desktop. Travel on mobile.**

以及：

> **Every screen should answer: What's next?**

後續所有新功能都可以用這兩句話判斷：

-   是否真的能讓規劃更方便？
-   是否真的能讓旅途中少操作幾次？
-   是否能更快知道下一步？
-   是否適合手機單手使用？

如果答案是否定的，就不應該排在優先開發項目。
